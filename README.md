# lead-webhook-api

[![CI](https://github.com/Aleksa5000/lead-webhook-api/actions/workflows/ci.yml/badge.svg)](https://github.com/Aleksa5000/lead-webhook-api/actions/workflows/ci.yml)

A small FastAPI service that catches leads from website forms, Typeform or Zapier-style webhooks, cleans and scores them, stores them without duplicates, and pings Slack when a hot one comes in.

## The problem it solves

Small businesses collect leads in five places (contact form, Typeform, Facebook ads, Zapier, a landing page) and then lose them: duplicates pile up, junk submissions clutter the inbox, and the sales person finds out about the one real prospect two days late.

This service is the missing glue. Every lead goes to one endpoint, where it is:

1. **Validated**: bad emails and broken payloads are rejected before they reach your data.
2. **Normalized**: emails lowercased, phone numbers reduced to a clean format.
3. **Deduplicated**: the same person submitting twice within 24 hours is stored once.
4. **Scored (0-100)**: business email, phone number, a detailed message and buying-intent words ("budget", "urgent", "quote") push the score up.
5. **Routed**: leads scoring 50 or more trigger a Slack message right away.
6. **Exportable**: browse them over the API or download a CSV for your CRM or spreadsheet.

## Features

- `POST /webhooks/lead` with Pydantic validation (`EmailStr`), `422` on bad input
- Optional shared-secret auth via `X-Webhook-Secret` (constant-time comparison)
- 24-hour email dedup (`{"status": "duplicate"}`, nothing stored twice)
- Transparent, easy-to-edit scoring rules
- SQLite storage using only the standard library, no database server needed
- Slack notifications in a background task; a failing Slack never breaks the request
- Lead list with `min_score` filter, and CSV export
- Interactive Swagger UI at `/docs` (auto-generated by FastAPI), ReDoc at `/redoc`
- Dockerfile, GitHub Actions CI, test suite

## API reference

| Method | Path | Description | Responses |
|--------|------|-------------|-----------|
| POST | `/webhooks/lead` | Receive a lead. Body: `name`, `email`, `message`, optional `phone`, `source` | `201` created, `200` duplicate, `401` bad secret, `422` invalid payload |
| GET | `/leads` | List leads, newest first. Optional `?min_score=0-100` | `200` JSON array |
| GET | `/leads/export.csv` | Download all leads as CSV | `200` text/csv |
| GET | `/health` | Liveness check | `200` `{"status": "ok"}` |
| GET | `/docs` | Swagger UI | |

## Example

Request (output below comes from a real run with uvicorn):

```bash
curl -X POST http://127.0.0.1:8000/webhooks/lead \
  -H "Content-Type: application/json" \
  -H "X-Webhook-Secret: demo-secret" \
  -d '{"name":"Jane Doe","email":"Jane.Doe@Acme.com","phone":"+1 (555) 123-4567","message":"We have a budget for a CRM integration and need a quote asap.","source":"typeform"}'
```

```json
{"status":"created","id":1,"score":86}
```

Sending the same email again within 24 hours:

```json
{"status":"duplicate"}
```

`GET /leads` shows the normalized record:

```json
[{"id":1,"name":"Jane Doe","email":"jane.doe@acme.com","phone":"+15551234567","message":"We have a budget for a CRM integration and need a quote asap.","source":"typeform","score":86,"created_at":"2026-10-12T08:04:09.195116+00:00"}]
```

A request without the correct secret returns `401`; an invalid payload returns `422`.

## Quickstart

### Local

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env   # optional; export the variables you want to use
uvicorn app:app --reload
```

Open http://127.0.0.1:8000/docs to try it in the browser.

### Docker

```bash
docker build -t lead-webhook-api .
docker run -p 8000:8000 \
  -e WEBHOOK_SECRET=change-me \
  -e SLACK_WEBHOOK_URL=https://hooks.slack.com/services/XXX \
  -v leads-data:/data \
  lead-webhook-api
```

The database lives in `/data/leads.db`, so the named volume keeps your leads across restarts.

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `WEBHOOK_SECRET` | unset | If set, requests must send a matching `X-Webhook-Secret` header, otherwise `401` |
| `SLACK_WEBHOOK_URL` | unset | Slack incoming webhook; leads with score >= 50 are posted here |
| `DATABASE_PATH` | `leads.db` | SQLite file location |

## Running tests

```bash
python -m pip install -r requirements.txt pytest
python -m pytest -q
```

Tests use FastAPI's `TestClient` with a temporary database, and Slack is mocked, so there is no network access.

## Tech stack

Python 3.11+, FastAPI, Pydantic v2, SQLite (`sqlite3`), httpx, uvicorn, pytest, Docker, GitHub Actions.
